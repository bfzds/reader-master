# EPUB 2 Directory Compatibility Design

## Goal

Import EPUB 2 books generated by PixivBatchDownloader with their original directory, without duplicate chapter entries or an in-text directory page.

## Scope

- Keep EPUB 3 navigation-document support.
- Read EPUB 2 NCX navigation through the OPF spine `toc` item or the NCX manifest media type.
- Skip only navigation documents that appear in the spine; do not discard ordinary chapters.
- Preserve existing book storage and reading UI contracts.
- Provide a browser-run regression page because this snapshot has no JavaScript test framework.

## Data Flow

`readEpub()` builds the OPF manifest and spine order. It first reads EPUB 3 `nav` when present; otherwise it resolves and reads the EPUB 2 NCX item. Both formats yield `{ href, title }` entries. While processing the spine, navigation-page paths from the OPF guide and EPUB 3 nav item are skipped. Each remaining spine document becomes plain text, and matching navigation entries become the persisted explicit index.

## Error Handling

Malformed or absent navigation data leaves the directory empty and retains the existing automatic-directory fallback. Missing spine files continue to be skipped as before. A malformed NCX must not prevent readable chapters from importing.

## Regression Coverage

The browser regression fixture simulates PixivBatchDownloader's EPUB 2 layout: root-level `book.opf` and `toc.ncx`, an `OEBPS/table-of-contents.html` guide entry in the spine, and two chapter files. It must prove that the explicit directory has two items and that the converted text excludes the generated directory page. It also covers an EPUB 3 navigation document to prevent regressions. Open this fixture in an external browser or the tReader runtime; do not use Codex's in-app browser because its temporary browser session can hang.

## Rollback

It saves the current parser as a `.bak` file before writing the rollback. This workspace is not a valid Git worktree, so a branch or commit is unavailable here.
