# 调试控制台位置持久化设计

## 目标

调试控制台在用户拖动后，关闭再打开、刷新页面或重启 tReader 时，都恢复到上一次停留的位置。

## 方案

- 使用现有的 IndexedDB 配置层保存内部键 `debug.logger_position`，值为 `{ left, top }` 像素坐标。
- 用户释放鼠标、结束拖动时再保存坐标，不在每次指针移动时写入配置。
- 面板插入页面后读取保存值；只有 `left` 和 `top` 都是有限数字时才应用。
- 应用保存值前复用现有边界限制逻辑，确保窗口尺寸变化后控制台仍完整地留在可视区域内。
- 没有保存值或保存值无效时，保留目前的右上角默认位置。
- 数据迁移只迁移用户阅读和通用设置，不迁移此设备相关的调试面板坐标。

## 影响范围

- 修改 `app_unpacked/src/js/ui/util/debug-logger.js`，负责读取、应用和保存坐标。
- 修改 `app_unpacked/src/js/ui/util/debug-logger-core.js`，提供可单测的坐标格式校验。
- 修改 `scripts/test-debug-logger.mjs`，覆盖有效坐标和无效配置的回退行为。

## 异常与验证

- 配置读取或写入失败由现有 `config` 层安全处理，控制台仍可正常显示和拖动。
- 无效、缺失或越界的坐标不导致报错；越界值会在显示时被限制在窗口范围内。
- 先新增失败测试，再实现最小改动；最后运行 Node 测试、JavaScript 语法检查和 Rust 测试。
