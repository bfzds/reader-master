# 迁移数据

## 1. 格式总览

| 格式 | 版本 | 用途 |
| --- | --- | --- |
| `treader-migration` | v2 | 合并已有书籍状态，可选正文和原文件。 |
| `treader-config` | v1 | 配置、阅读元数据和索引，不包含正文与原文件。 |
| 旧数组备份 | legacy | 导入书籍；重复书籍按旧逻辑跳过，不用于合并状态。 |

`format` 和 `version` 必须匹配。未知版本或无效 payload 应报错，不会被静默猜测为其他格式。

## 2. v2 内容

默认可包含配置、书架元数据、目录、书签、阅读进度和书架顺序。导出选项还可以包含：

- **正文**：在新环境保存为当前书籍正文；在需要时可生成 UTF-8 `.txt` 副本；
- **原文件**：以可迁移的 Base64 字节表示保存，适合保留 EPUB 原始资源和图片。

正文与原文件同时导出会重复保存内容，迁移 JSON 会明显变大。是否包含这两类数据由导出选项决定。

## 3. 匹配与冲突

书籍按以下线索逐级匹配：

1. 原始文件哈希；
2. 正文哈希与正文长度；
3. 来源文件名；
4. 书名。

书名不是可靠的唯一身份。多候选、哈希冲突或多个迁移条目命中同一目标时，不自动合并，交由冲突解析器处理；同一目标不能被多个条目重复使用。

匹配成功后保留新环境书籍的 ID，按合并规则恢复阅读位置、目录、书签、时间和顺序。默认保护目标已有正文；缺失正文时可恢复迁移正文，显式覆盖选项才改变已有正文。

找不到本体时：

- 有正文：创建完整书籍；
- 没有正文：创建 `configOnly` 占位记录；
- 空字符串正文是有效正文，不等同于“缺少正文”。

冲突确认和目标匹配完成前，不应写入默认外部 source；source 保存失败必须进入失败统计，不应伪装成恢复成功。

## 4. 本地状态与权限

以下内容不携带跨设备的授权意义：

- `sourceFolderPath`（旧来源路径元数据）；
- `sourceFolderId`（当前设备 native registry 的 opaque ID）；
- 旧环境绝对路径；
- 当前设备文件夹权限和 `import-folders.json`；
- `debug.show_console` 与其他环境相关设置。

`sourceFolderPath` 可以作为来源元数据或匹配线索保留，但不能直接变成当前设备 native 授权。`sourceFolderId` 只对生成它的设备 registry 有效，不应手工复制到另一台设备。恢复原文件时，应在新环境重新选择目录并建立新的 folder registry 关系。

## 5. 兼容格式

`treader-config` v1 只恢复支持的配置与阅读状态；旧数组备份仍可导入新书籍，但使用旧的重复跳过语义，不等同于 v2 的冲突合并。导入前必须校验格式、版本和书籍数组，非法条目应跳过或计入失败统计。

详细实现位于 `app_unpacked/src/js/data/file.js`、`migration-source.js`、`migration-conflict.js` 和 `migration-export.js`。
