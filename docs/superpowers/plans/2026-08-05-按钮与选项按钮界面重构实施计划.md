# 按钮与选项按钮 UI 重构实施计划

> **给执行者：** 按任务顺序执行本计划。每项任务完成后运行对应测试和最小人工检查，再进入下一项。不要自动提交 Git，最终是否提交由用户决定。

**目标：** 建立统一的按钮和选项按钮视觉体系，重点改善配置页、菜单、批量操作、弹窗和阅读器控制按钮的层级、状态与间距，同时保持现有功能、配置数据和阅读行为不变。

**架构：** 继续使用项目现有的原生 ES 模块、HTML 模板和外部 CSS，不引入新的 UI 框架或运行时样式注入。按钮通过语义 class 和主题 token 分层，配置页选项继续由现有 ConfigOption、ItemList 和 template 负责生成；本次只调整生成的 class、结构和样式，不改变点击回调、配置读写和页面路由。

**技术栈：** 原生 HTML、CSS、CSS 自定义属性、原生 ES 模块、Node node:test、现有 Tauri/WebView2 运行环境。

## 全局约束

- 前端源代码目录保持为 app_unpacked/src/。
- 不新增第三方依赖，不引入 React、Vue、Tailwind 或 CSS-in-JS。
- 不改变配置项名称、配置值、持久化格式、页面 URL、阅读模式和文件导入逻辑。
- 不改变按钮触发的业务动作，只改变按钮的视觉层级、class、布局和反馈状态。
- 本项目不需要无障碍功能。本次不新增 ARIA、读屏文本、键盘导航、焦点管理或无障碍验收项；已有代码中的相关属性不主动删除。
- 保留现有 MPL 许可证头。
- 继续使用现有 light.css、dark.css 主题体系，新增 token 必须在两个主题中同时定义。
- 不使用运行时注入的 style；按钮和选项样式全部放在现有 CSS 文件中。
- 基础按钮 class 必须使用 `button.ui-button`、`button.ui-icon-button`、`button.ui-option-button` 等至少包含元素选择器的复合选择器，避免被 input.css 中 `button[type="button"]` 的 reset 规则覆盖。
- 基础按钮 class 只负责颜色、边框和状态；顶部栏、底部栏、阅读器控制区和菜单的尺寸与定位继续由各自区域规则负责，不使用全局 `min-width` 或 `min-height` 强行覆盖既有布局。
- CSS 只为已有 `disabled` 属性提供视觉样式，不新增点击拦截，不修改现有 disabled 条件和业务状态。
- 不修改 src-tauri/、artifacts/、asar_extracted/、node_modules/、启动脚本和用户已有未追踪文件。
- 不将本阶段改造成完整设计系统；只增加能够减少重复、并且马上被现有页面使用的基础 class。

### 本次要解决的问题

1. 普通操作按钮、图标按钮、菜单项和批量按钮没有统一的层级命名。
2. 配置页的选项行、选择列表、字体上传项和开关虽然功能一致，但视觉状态不统一。
3. 选中、悬停、按下、禁用和危险操作颜色分散在多个 CSS 规则中。
4. 部分弹窗按钮使用 options.js 内联样式，无法稳定跟随明暗主题。
5. 按钮尺寸和间距在顶部栏、底部栏、配置页、列表页之间不一致。
6. 新增样式容易与现有 Phase 1 Modal/Toast、批量栏和主题 token 发生命名冲突，因此必须先固定 token 表。

### 不在本次范围内

- 不重写阅读器分页、目录、书签、搜索业务逻辑。
- 不改变配置页的分组和页面结构，不增加新的设置项。
- 不替换现有 ItemList 组件。
- 不把所有文字操作都改成图标按钮。
- 不新增专门的无障碍功能。

## 二、统一视觉契约

### 按钮层级

| 层级 | class | 用途 |
| --- | --- | --- |
| 基础按钮 | .ui-button | 所有需要文字标签的普通按钮 |
| 主要按钮 | .ui-button-primary | 确认、导出、提交等当前区域的主要动作 |
| 次要按钮 | .ui-button-secondary | 取消、返回、辅助动作 |
| 危险按钮 | .ui-button-danger | 删除、清空等不可逆操作 |
| 图标按钮 | .ui-icon-button | 顶部栏、底部栏和阅读器控制按钮 |
| 选项按钮 | .ui-option-button | 配置页选择项、菜单项和可选设置项 |

同一个按钮可以同时使用基础 class 和层级 class，例如：

~~~html
<button class="ui-button ui-button-primary">确认</button>
<button class="ui-button ui-button-danger">删除</button>
<button class="ui-icon-button">设置</button>
<button class="ui-option-button">翻页模式</button>
~~~

### 状态

- 默认：清晰区分背景、文字和边框。
- 悬停：只改变背景或边框，不改变布局尺寸。
- 按下：使用更深的状态色，不产生位移。
- 选中：由现有 `.list-item-selected` 状态驱动选项按钮的选中背景和文字颜色，并保留现有选中图标机制；不新增 `.ui-option-button-selected` 状态类。
- 禁用：只为已有 `disabled` 属性降低对比度并显示禁用状态，不改变相邻元素位置，也不新增点击拦截。
- 危险：只用于删除、清空等动作，不把普通错误提示按钮染成危险色。

### Token 命名表与现有 token 映射

以下命名是本计划唯一允许的新 token 名称，避免计划和实现出现两套名称：

~~~css
--button-background
--button-color
--button-hover-background
--button-active-background
--button-disabled-background
--button-disabled-color
--button-primary-background
--button-primary-color
--option-background
--option-color
--option-hover-background
--option-active-background
--option-selected-background
--option-selected-color
--option-divider-color
--switch-off-background
--switch-on-background
--switch-thumb-background
~~~

按钮边框直接复用现有 `--border-color`，危险操作直接复用现有 `--danger-color`，不新增同义的 button border 或 danger token。现有 Phase 1 token 继续沿用，具体映射如下：

| 控件 | 视觉来源 | 约束 |
| --- | --- | --- |
| `.modal-button-confirm` | `.ui-button-primary` 的 `--button-primary-*` | 保留 `.modal-button-confirm` 类名，作为主要按钮别名，不删除现有选择器。 |
| `.modal-button-cancel`、`.modal-button-close` | `.ui-button` 的普通 token | 保留 Modal 现有类名，取消按钮不使用危险色。 |
| `.batch-select-all` | `.ui-button-secondary` 的普通 token | 保留批量栏布局和禁用逻辑。 |
| `.batch-delete` | 现有 `--danger-color` | 不新增 `--button-danger-*`；删除按钮仍由 `.batch-delete` 控制危险边框和文字。 |
| `.read-meta` | 现有 `--reader-meta-color` | 继续只使用这个合法的 Phase 1 token，不检查或禁止它。 |
| `.screen-option-item` | `.ui-option-button` 的 `--option-*` | 保留原 class，并追加 `.ui-option-button`；菜单项单独消费 `--option-divider-color`，旧的 `--menu-background`、`--menu-color` 在迁移完成后不再被菜单使用。 |

新增 token 必须在 light.css 和 dark.css 中拥有对应值，并由静态测试检查。静态测试只检查本计划新增 token 的定义和消费点，不使用全局“禁止所有其它 token 名称”的脆弱负向匹配。
